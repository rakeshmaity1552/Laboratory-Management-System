# Entity Relationship Diagram (ERD)

## Laboratory Management System

## 1. Entity overview

The database uses SQLite3. The primary entities are users, PCs, and
tickets. Supporting entities preserve comments, ticket status changes,
and administrative audit events.

## 3. Table specifications

### 3.1 `users`

Stores student/lab-user and administrator accounts.

  Column           Type      Constraints / purpose
  ---------------- --------- ------------------------------------------------------
  user_id          INTEGER   Primary key, autoincrement
  full_name        TEXT      Required
  username         TEXT      Required, unique
  email            TEXT      Optional or required by policy, unique when supplied
  password_hash    TEXT      Required; generated by PHP `password_hash()`
  role             TEXT      `user` or `admin`
  account_status   TEXT      `active` or `disabled`
  created_at       TEXT      UTC timestamp
  updated_at       TEXT      UTC timestamp

### 3.2 `pcs`

Stores the laboratory's computer inventory.

  -----------------------------------------------------------------------
  Column                  Type                    Constraints / purpose
  ----------------------- ----------------------- -----------------------
  pc_id                   INTEGER                 Primary key,
                                                  autoincrement

  pc_code                 TEXT                    Required, unique,
                                                  e.g. `PC-01`

  pc_name                 TEXT                    Optional display name

  location                TEXT                    Optional lab/room

  operational_status      TEXT                    `Working`,
                                                  `Reported Issue`,
                                                  `Under Maintenance`,
                                                  `Out of Service`,
                                                  `Inactive`

  notes                   TEXT                    Optional

  is_active               INTEGER                 1 active, 0 inactive

  created_at              TEXT                    UTC timestamp

  updated_at              TEXT                    UTC timestamp
  -----------------------------------------------------------------------

Seed 30 records with codes `PC-01` through `PC-30`.

### 3.3 `tickets`

Stores issue reports.

  -----------------------------------------------------------------------
  Column                  Type                    Constraints / purpose
  ----------------------- ----------------------- -----------------------
  ticket_id               INTEGER                 Primary key,
                                                  autoincrement

  ticket_number           TEXT                    Required, unique,
                                                  e.g. `LAB-2026-00001`

  pc_id                   INTEGER                 FK to `pcs.pc_id`

  reporter_id             INTEGER                 FK to `users.user_id`

  category                TEXT                    Controlled issue
                                                  category

  priority                TEXT                    `Low`, `Medium`,
                                                  `High`, `Critical`

  title                   TEXT                    Short issue summary

  description             TEXT                    Detailed issue
                                                  description

  status                  TEXT                    `Open`, `Acknowledged`,
                                                  `In Progress`,
                                                  `Waiting for Parts`,
                                                  `Resolved`, `Closed`,
                                                  `Rejected`

  resolution_notes        TEXT                    Nullable

  resolved_by             INTEGER                 Nullable FK to users

  resolved_at             TEXT                    Nullable timestamp

  created_at              TEXT                    UTC timestamp

  updated_at              TEXT                    UTC timestamp
  -----------------------------------------------------------------------

### 3.4 `ticket_comments`

Stores user/admin discussion and follow-up notes.

  Column         Type      Constraints / purpose
  -------------- --------- -----------------------
  comment_id     INTEGER   Primary key
  ticket_id      INTEGER   FK to tickets
  user_id        INTEGER   FK to users
  comment_text   TEXT      Required
  created_at     TEXT      UTC timestamp

### 3.5 `ticket_status_history`

Records every ticket status transition.

  Column       Type      Constraints / purpose
  ------------ --------- ----------------------------
  history_id   INTEGER   Primary key
  ticket_id    INTEGER   FK to tickets
  changed_by   INTEGER   FK to users
  old_status   TEXT      Nullable for initial state
  new_status   TEXT      Required
  note         TEXT      Optional
  changed_at   TEXT      UTC timestamp

### 3.6 `audit_logs`

Records important administrative actions.

  Column        Type      Constraints / purpose
  ------------- --------- -----------------------------------------------
  audit_id      INTEGER   Primary key
  user_id       INTEGER   FK to users
  action        TEXT      e.g. `PC_STATUS_UPDATED`
  entity_type   TEXT      e.g. `pc`, `ticket`, `user`
  entity_id     INTEGER   ID of affected record
  details       TEXT      Safe descriptive details; never store secrets
  created_at    TEXT      UTC timestamp

## 4. Relationships and cardinality

-   One user can report zero or many tickets; each ticket has exactly
    one reporter.
-   One PC can have zero or many tickets over time; each ticket concerns
    one PC.
-   One ticket can have zero or many comments.
-   One user can write zero or many comments.
-   One ticket can have zero or many status-history records.
-   One user can perform zero or many status changes and audit actions.
-   A resolved ticket may reference the admin who resolved it.

## 5. Important database rules

1.  Enable foreign keys for every SQLite connection:
    `PRAGMA foreign_keys = ON;`.
2.  Use `ON DELETE RESTRICT` or soft-deactivation for users and PCs to
    preserve history.
3.  Do not delete tickets during ordinary operation.
4.  Use unique constraints on `username`, `email` (if mandatory),
    `pc_code`, and `ticket_number`.
5.  Add indexes on `tickets(status)`, `tickets(pc_id)`,
    `tickets(reporter_id)`, and `tickets(created_at)`.
6.  Store timestamps consistently in UTC (ISO 8601 text is acceptable);
    convert to local time for display.
7.  Keep PC operational status separate from ticket status.

## 6. Suggested SQLite schema

``` sql
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS users (
    user_id INTEGER PRIMARY KEY AUTOINCREMENT,
    full_name TEXT NOT NULL,
    username TEXT NOT NULL UNIQUE,
    email TEXT UNIQUE,
    password_hash TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'user'
        CHECK (role IN ('user', 'admin')),
    account_status TEXT NOT NULL DEFAULT 'active'
        CHECK (account_status IN ('active', 'disabled')),
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS pcs (
    pc_id INTEGER PRIMARY KEY AUTOINCREMENT,
    pc_code TEXT NOT NULL UNIQUE,
    pc_name TEXT,
    location TEXT,
    operational_status TEXT NOT NULL DEFAULT 'Working'
        CHECK (operational_status IN
        ('Working', 'Reported Issue', 'Under Maintenance', 'Out of Service', 'Inactive')),
    notes TEXT,
    is_active INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0, 1)),
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS tickets (
    ticket_id INTEGER PRIMARY KEY AUTOINCREMENT,
    ticket_number TEXT NOT NULL UNIQUE,
    pc_id INTEGER NOT NULL,
    reporter_id INTEGER NOT NULL,
    category TEXT NOT NULL,
    priority TEXT NOT NULL DEFAULT 'Medium'
        CHECK (priority IN ('Low', 'Medium', 'High', 'Critical')),
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'Open'
        CHECK (status IN ('Open', 'Acknowledged', 'In Progress',
        'Waiting for Parts', 'Resolved', 'Closed', 'Rejected')),
    resolution_notes TEXT,
    resolved_by INTEGER,
    resolved_at TEXT,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (pc_id) REFERENCES pcs(pc_id) ON DELETE RESTRICT,
    FOREIGN KEY (reporter_id) REFERENCES users(user_id) ON DELETE RESTRICT,
    FOREIGN KEY (resolved_by) REFERENCES users(user_id) ON DELETE RESTRICT
);

CREATE TABLE IF NOT EXISTS ticket_comments (
    comment_id INTEGER PRIMARY KEY AUTOINCREMENT,
    ticket_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    comment_text TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (ticket_id) REFERENCES tickets(ticket_id) ON DELETE RESTRICT,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE RESTRICT
);

CREATE TABLE IF NOT EXISTS ticket_status_history (
    history_id INTEGER PRIMARY KEY AUTOINCREMENT,
    ticket_id INTEGER NOT NULL,
    changed_by INTEGER NOT NULL,
    old_status TEXT,
    new_status TEXT NOT NULL,
    note TEXT,
    changed_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (ticket_id) REFERENCES tickets(ticket_id) ON DELETE RESTRICT,
    FOREIGN KEY (changed_by) REFERENCES users(user_id) ON DELETE RESTRICT
);

CREATE TABLE IF NOT EXISTS audit_logs (
    audit_id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER,
    action TEXT NOT NULL,
    entity_type TEXT NOT NULL,
    entity_id INTEGER,
    details TEXT,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_tickets_status ON tickets(status);
CREATE INDEX IF NOT EXISTS idx_tickets_pc_id ON tickets(pc_id);
CREATE INDEX IF NOT EXISTS idx_tickets_reporter_id ON tickets(reporter_id);
CREATE INDEX IF NOT EXISTS idx_tickets_created_at ON tickets(created_at);
```
